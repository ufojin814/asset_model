## 2026-10-14 · 迭代三：深度研究评级缺陷修复（金融业评级 + 报告字段）

### 背景
迭代二的 NL 端到端测试跑通后，继续开发中发现深度研究（`/api/nl-deep`、`deepResearch`）存在两类缺陷，均会直接影响「对客/对内」呈现的可信度（用户为银行财富管理条线，银行股是高频分析对象）。

### 缺陷与修复（根因）
- **① 深度报告缺顶层 `rating` 字段（阻断性）**：`deepResearch` 返回 `{ok, ticker, name, markdown, json}`，评级只挂在 `json.rating` 内，而 `server.js` 取 `dr.rating`（顶层）导致 NL 端到端断言「含评级」失败。已补顶层 `rating` 字段。
- **② 银行被误判 T5 回避池 + 致命证伪（建模缺陷）**：`tierRating` 与 `falsificationList` 直接套用 **Altman Z / Piotroski F**——二者基于「营运资本/总资产」等制造业口径，金融机构负债结构与制造业迥异；Wind 对银行不返回 `wc/re/ebit/ta` 等字段，使 `altmanZ(f)` 恒为 0 → `z<1.81` → 强行判 **T5 回避池** 并打出「财务安全边际不足、存在违约/退市风险」**致命证伪点**。对招商银行、兴业银行均触发，明显失真。
  - 新增 `isFinancial(stock)`（`src/stockSelector.js`）：用 **行业 + 主题 + 名称** 判定（Wind 对部分标的 `industry` 返回空，故纳入名称兜底，A 股金融股名称稳定含「银行/证券/保险」）。
  - `scoreStock` 对金融业把 `piotroskiF`/`altmanZ` 置 `null` → 对应子项回到中性 50 分，不再误杀。
  - `tierRating` 新增金融业独立分支：用 **估值安全边际（PE/PB 历史分位 + 破净 PB<1）+ 盈利质量（ROE≥10% / ROIC≥8%）+ 12m 动量** 评级，避用 Altman Z / Piotroski F。
  - `falsificationList` 对金融业跳过 Altman Z 致命点。
- **③ ROE/ROIC 展示格式错误（显示缺陷）**：报告表格原写法 `ROE=${f.roe}%` 把小数（如 0.0584）直接当成百分比显示成 `0.0584%`。已改为 `round(f.roe*100,2)` → 正确显示 `5.84%`，金融业另标注「F-Score / Altman Z 金融业不适用」。

### 修复后实测（真实 Wind 数据）
| 标的 | 修订前 | 修订后 | 说明 |
|------|--------|--------|------|
| 招商银行 600036.SH | T5 回避池（致命） | **T3 备选池** | PE 分位 84.6% 偏贵、ROE 5.84% 一般，但破净(PB 0.94)且 12m +7.14% 动量，无致命点 |
| 兴业银行 601166.SH | T5 回避池（致命） | **T4 观察池** | 深度破净(PB 0.46 / 25 分位)、但 12m −8.83% 动量负、ROE 4.45% 偏低、盈利负增，无致命点 |

> 另发现 兴业银行  fundamentals 曾因 **Wind 取数瞬时返回空** 而全 null（非代码 bug）；删除缓存重新拉取即正常填充。属偶发网络/接口抖动，已通过 24h 缓存 + 三层降级缓解。

## 2026-10-14 · 迭代四：三大体验缺陷修复（选股截断 / 宏观依据 / 名称解析）

### 用户反馈（原文要点）

### 缺陷与修复（根因）

#### ① 主题选股截断（前端渲染不全 + 潜在滚动锁）
- **根因**：`public/js/app.js` 的 `runSelection` 只遍历 `th.top`（Top3）渲染，主题含 >3 只标的时（如银行 4 只）第 4 只被丢弃；`html,body{height:100%}` 在个别布局下存在溢出裁切风险。
- **修复**：
  - `app.js` 改为遍历完整 `th.ranked`（全量标的），前 `topN` 只加 `.r-top` 高亮并打「入选」标签。
  - `style.css` 将 `html,body{height:100%}` 放宽为 `html,body{min-height:100%}`，保证超长内容整页正常滚动。
  - API 本就返回 `ranked` 全量，无需改后端（已核验 `/api/select?theme=bank` 返回 `count=4 / ranked.length=4`）。

#### ② 宏观研判补充依据（每期限「依据 + 结论」）
- **根因**：`runMacro` 仅渲染概率条，未解释结论由哪些因子驱动。
- **修复**：
  - `src/macroAnalyzer.js` 新增 `buildHorizonExplain(contrib)`：取对各期限倾斜度贡献绝对值最大的前 3 个因子，结合 `config/macro-indicators.json` 的 `factorDocs` 中文标签，标记利好/利空与贡献值；`analyzeMacro` 把 `explain` 挂到每个 `byHorizon[h]`。
  - `app.js` `runMacro` 在每个期限条下渲染「研判依据：<因子芯片(利好绿/利空红)> … 结论：<stance>」。
  - `server.js buildMacroMarkdown` 同步在宏观报告表新增「研判依据（主因）」列，资料库落盘报告亦携带。

#### ③ 中国卫通无法解析（NL 名称 → Wind 代码）
- **根因**：
  - 演示 `aliasMap`（`getAliasMap`）只含 `data/stocks/*.json` 种子标的，「中国卫通」不在其中 → `handleNLDeep` 直接判未命中。
  - 即使走 Wind，原 `extractWindCode` 用 `pick(obj,['代码','wind代码',...])` 精确匹配，而 Wind `get_stock_basicinfo` 返回的代码列名是 **`Wind代码`**（大小写不匹配）→ 解析为 null；`get_stock_quote` 用名称查询又直接返回「行情数据查询失败」。
- **修复**：
  - `src/dataProvider.js` 新增 `resolveWindCode(name)`：先调 `stock_data.get_stock_basicinfo`（NL「查询<名称>股票的基本档案，返回代码、简称、所属行业」），再兜底 `get_stock_quote`；`extractWindCode` 改为**遍历所有键名**匹配「代码/code」并提取首个 `6 位数字(.SH/.SZ)` 形态，规范化 `XXXXXX.SH/SZ`（6 开头→SH，0/3 开头→SZ）。
  - `server.js handleNLDeep`：本地/演示集未命中时 `await resolveWindCode(rawName)` 经 Wind 解析，解析成功则补 `code` 与 `resolvedBy:'wind'` 再进入 `deepResearch`。
- **实测**：输入「分析中国卫通」→ 经 Wind 解析为 **601698.SH** → 深度研究成功（数据源：**Wind 真实数据（S级）**）。

#### 附带修复：深度研究报告数据源标注失真（数据真实性）
- `deepResearch` 实际已通过 `getProvider().getStock()` 取 Wind 真实数据，但报告模板硬编码「数据源：local 演示数据」，与真实来源不符（违反零虚构原则）。
- 已按 `stock._source`（wind/akshare/local-demo-fallback）动态生成 `srcLabel`，同步修正报告头、节点0 与结论处的「关键假设与数据源」措辞。

## 迭代五：主题识别精度 + 多标的雷达对比（用户反馈驱动）

### 用户反馈（两条）
1. **主题识别不清晰**：输入「芯片，养老，医疗，电力，ai，银行」多个概念板块，结果只筛选出「芯片 / 银行 / 光通信」——漏掉养老、医疗、电力、AI，且**误加了光通信**。
2. **多标的共享一个雷达图**：每个板块的多只标的为何只用一张雷达图？是否是"都差不多"？判断是否需要每只标的单独列雷达图。

### 根因分析
- **识别窄 + 误匹配**：旧 `config/themes.json` 仅 5 个主题（光通信/芯片/商业航天/黄金/银行），养老/医疗/电力/AI 根本不在主题表里 → 漏识别；旧 `heuristicParse` 按主题**描述文字子串盲匹配**（如描述含"AI 算力驱动…"），导致输入里的 "AI" 误中光通信。
- **雷达只画第一名**：前端 `runSelection` 原本只取 `ranked[0]` 画单张雷达，板块内其余标的无图，给人"共享一张图"的错觉；且无法横向比较。

### 修复清单
#### ① 主题识别：受控映射 + 动态概念兜底
- `config/themes.json` 由 5 → **10 个主题**，补齐真实标的：新增 `medical 医疗/医药`、`pension 养老`、`power 电力`、`ai 人工智能`、`newenergy 新能源`（光通信/芯片/商业航天/黄金/银行保留）。
- `src/nlIntake.js` 引入受控 **`CONCEPT_MAP`**（key → `{triggers:[触发词], q:Wind查询短语}`），覆盖全部 10 主题 + 6 个自由概念（低空经济/机器人/自动驾驶/元宇宙/消费/军工）。
  - `heuristicParse` 改为**受控触发词匹配**：命中主题键 → 进 `themes`；否则 → 进 `concepts`（交 Wind 兜底）；不再做描述子串噪声匹配。
  - `parseIntent` 的 Hermes prompt 新增第 3 个返回字段 `concepts`，并**与 heuristic.concepts 合并**，双路保险。
- `server.js handleNLThemes`：处理 `intent.concepts`——若命中已知主题（键/名称，双向子串防重复）走 `selectStocks`，否则 `searchWindStocks('筛选A股{概念}概念相关股票，取前8只')` → `selectByTickers`；`seenKey` 去重避免同主题双计。
